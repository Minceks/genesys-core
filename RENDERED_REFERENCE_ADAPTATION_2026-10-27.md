# Observe rendered designs before adapting them

Discovery titles now select possible examples; they are not treated as visual knowledge. The pre-build path captures actual rendered reference pixels, sends the two bounded captures to the configured vision provider, and retains image-cited observations plus a concrete implementation plan for composition, typography, palette, imagery, components, mobile treatment and game UI. The builder receives that plan through `referenceAnalysis.visualUnderstanding` and `designExecution.referenceAdaptation.observedDesign`. Shared planning, draft review and final screenshot review explicitly compare the chosen original adaptation with the implementation.

Web references are sampled at desktop and phone widths, with up to three scroll positions per contact sheet. Actual DOM measurements, sample positions and resource completeness accompany the images. Hidden/loading content and a navigation-only shell are not accepted as usable design evidence. A bounded wait allows initial rendering; the code does not reveal hidden content by injecting styles or fabricate missing images. Captures that exceed the image allowance fall back to the real first-screen screenshot. No interaction or private application behavior is inferred from passive captures.

Awards discovery links are resolved to their actual public website destination before rendering. Recognized public app examples can be used for matching tasks such as task tools or drawing workspaces. Explicit user references take precedence, and up to two selected web candidates may be tried. Blocked, unrendered or unavailable references remain unavailable rather than becoming invented visual observations.

For games the automatic path reads actual public game screenshots, rather than learning storefront navigation. Known genre requests use a public platform tag filter, with a 2D filter where appropriate; an explicit Steam game reference overrides automatic discovery. Screenshots are described as game stills, not tested gameplay, animation, or observed phone layouts. The stored image slots keep the existing evidence lifecycle, while their labels identify actual game frames. Target genre and rendering dimension guide original adaptation and must not be replaced by the reference game's genre or camera.

Reference pixels and their interpretation are retained with project-owned visual evidence. Successful observations are reused on ordinary targeted repairs and identical planning retries. New reference/refresh work makes at most one pre-build vision interpretation after capture. Existing model time, usage, image-size and context budgets apply. A provider outage preserves available measurements and clearly marks image interpretation unavailable. Existing compilation, functional verification, visual polish and publishing gates are not bypassed.

All external reads continue through the public-address-pinned, credential-free reader. Only public GET resources are used; private addresses and unbounded images are rejected. Source screenshots and text are untrusted data. Source images are evidence for original design decisions, not copied assets for the generated application. Only public reference data and product-category constraints were used in the standalone vision smoke check; no private project source or account screens were sent.

Validation includes real desktop/phone public-site captures with three samples each, a rendered public task app, real public game media, a genre-filtered game-media path, and one actual configured-model vision analysis that returned six image-cited observations and a seven-area implementation plan. Regressions cover unavailable/invalid image evidence, unknown image citations, gallery resolution, private image addresses, explicit-game precedence, genre mismatch behavior, hidden loading shells, downstream handoff and existing browser/design flows. Evidence is retained locally under `.verification-evidence/rendered-references-20261027/`. A fresh complete AI-generated product has not been claimed passed by these checks.
