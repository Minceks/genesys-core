# Senior engineering and current product research

The builder now receives a shared senior product-engineering policy and a persisted `engineeringStrategy`. It identifies the audience, primary journey, constraints, practical implementation alternatives, architecture/data contracts, scope and verification outcomes. The policy applies to the ordinary implementation path and parallel draft/review paths. A role label is not treated as evidence of quality: compilation, functional browser checks and visual review remain separate.

The saved design brief also contains `trendIntelligence`: source URLs, retrieval dates, bounded current examples and an honest evidence status. New builds and redesigns research the appropriate product family. Explicit requests to follow current design trends refresh the direction. Targeted repairs preserve design, product identity, dependencies and saved data. Repeated initial planning requests reuse the brief; an expired research snapshot can refresh without restarting the product design. Successful public snapshots are cached for six hours and unavailable sources for five minutes.

The sources are [Product Hunt's official launch feed](https://help.producthunt.com/en/articles/484970-does-product-hunt-have-an-rss-feed), [Awwwards website selections](https://www.awwwards.com/websites/), [itch.io discovery listings](https://itch.io/games/new-and-popular), and [Steam's most-played chart](https://store.steampowered.com/charts/mostplayed). The Steam adapter reads Valve's chart API and resolves only three numeric app IDs to names through the public store API. These are different signals: new launches and curated examples are not global popularity rankings. Steam positions are explicitly platform-specific and keep their snapshot date. Names and dates do not prove a visual treatment or game mechanic is trending.

The agent must select zero to three relevant adaptations and explain fit, source/date or curated basis, user benefit and rejected mismatches. The user's requested genre, brand, reference, minimal/retro style, feature scope and budget take precedence. The policy does not turn a puzzle game into a shooter or add AI/accounts/payments/animation merely because those appear in a listing. Curated product-fit patterns remain available when research is stale, blocked or unavailable and are not represented as live popularity evidence.

Research uses fixed public URLs, no credentials or user/project query payloads, bounded response sizes/time, no arbitrary redirects, at most eight extracted entries and bounded prompt observations. Only three chart name lookups are permitted. Feed XML entity declarations are rejected; tracking queries/fragments are removed from example URLs. Source content is untrusted data, never instructions. Discovery galleries and product listings are excluded from automatic visual-reference capture so that a playable game is not styled like a game store. Existing explicit visual references still work.

The strategy and evidence travel to specification generation, design execution, shared draft planning and review, rather than existing only in a saved metadata file. Optional inspirations do not automatically become mandatory acceptance criteria or authorize changes outside a targeted repair. No publishing or functional verification gate is bypassed.

Live public-source smoke checks found launch entries, website selections and Steam chart entries. itch.io returned an access challenge and was left unavailable. The smoke checks sent no project source to a model and started no new paid generation. Regression coverage includes feed formats, unsafe XML, bounded parsing, fresh/stale evidence, caches, scope/genre preservation, source-to-planner/reviewer propagation and existing design/build behavior. Evidence is retained under `.verification-evidence/senior-trends-20261026/`.
