# Default delivery craft

The user approved the finish of the repaired Nightfall game and booking app and requested that this become the agent default. This change generalizes the process, not those products' colors, layout or feature set.

The shared builder/reviewer standard and saved design execution now contain a delivery playbook: concrete art direction, original adaptations of observed references, complete state transitions, authoritative state ownership, dependent-selection invalidation, local dates, reachable validation and phone navigation clearance. Existing user scope, style, abstract games and minimal products remain authoritative. Source review explicitly checks these recurring failure modes.

Full builds and saved verification retries now capture up to three states immediately after real browser workflows assert their outcome, before independent-check cleanup. Each state is resized to desktop and phone, checked for horizontal overflow and fixed/sticky controls covering enabled actions, and captured without clicks, navigation or storage injection. Viewport and scroll are restored. At most four screenshots enter a separate bounded workflow visual review; screenshot resizing is explicitly not independent phone functional verification. Narrow edits retain their limited scope. Existing visual-review opt-out remains respected.

The first major workflow design finding offers one targeted polish pass. Remaining major findings after recheck mark verification incomplete and preserve the build instead of publishing it as reviewed. Provider or capture outages are disclosed as unavailable rather than invented application defects. Reports retain workflow view metadata and screenshot-review evidence separately from functional passes. Existing fingerprint-pinned passing-plan reuse remains in place.

Validation: 87 isolated regression tests passed, followed by 31 focused checks after strengthening the remaining-major-findings gate and capture-failure handling. The actual repaired booking bundle still passed all five browser requirements at both 1440px and 390px; the actual game bundle passed all eight at both widths, with workflow capture enabled, six state screenshots per run and zero runtime errors. The new reachability check finds an intentionally covered Book control and clears when space is reserved; active modal controls exclude the inert/background task. No private project content was sent to a model in these checks. New production workflow screenshot reviews use the existing configured review provider and bounded review budget.
