# Provider fallback, inspection limits and verification handoff

The latest failed redesign was job `842ebaba22f5457ea74eaf92cf50a112` for project `6789d7c7-511f-44df-bede-ac5a339d5497`. Sandbox startup worked. An OpenAI request timed out, fallback to Gemini succeeded, and excessive rereading consumed the implementation steps. At step 19 the coordinator returned before compiling or verifying the saved edits. A misplaced function-local logging import from the prior logging change also raised an UnboundLocalError during project inspection, dropping useful source context. The latter is corrected by using the existing module logger.

The inspection budget now covers every phase and provider: four read/list attempts before the first edit, two between subsequent edits, and two in repair. It is enforced both in offered tools and while processing a batch. A provider switch retains the same budget and source context. Completed edits reset the two-read allowance. Source safety guards and independent validation are unchanged.

At the implementation step limit, or when only the verification reserve remains, saved edits enter the existing mandatory build/preview/browser flow instead of failing solely because no final model message arrived. A model-request deadline exhausted after edits also hands off without replaying an old response. Compilation alone cannot create a verified checkpoint; unfinished features, missing presentation changes and runtime failures still require repair or remain unverified.

OpenAI requests have an explicit 90-second ordinary timeout, a 120-second structured-plan cap, and a 60-second visual-review cap, each clamped to remaining request time. A nested context cannot extend the parent deadline. Implementation/fallback calls reserve time for mandatory checks, and expired contexts cannot start another model request. SDK retries remain disabled to avoid multiplying retry loops and costs. No model selection, account spending allowance or verification/publishing gate is weakened. Expected network timeout logs are concise; unexpected errors retain tracebacks. Timeout behavior follows the [official OpenAI Python SDK controls](https://developers.openai.com/api/reference/python).

Requests such as “better UI designe” now select redesign behavior. A generic necessary-evidence check requires actual presentation source changes; metadata, titles, favicons, planning files or comments alone cannot establish a redesign. React/Vue/Svelte, stylesheets, plain HTML and canvas rendering are supported. This is eligibility for visual review, not an aesthetic pass. A missing presentation change enters the existing repair loop.
