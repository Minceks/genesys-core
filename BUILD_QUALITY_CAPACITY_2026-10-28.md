# Build quality capacity and recovery

The weak new zombie build used gpt-5-mini with low reasoning, a 6,000-token initial output cap, a 24,000-token input budget, and a ten-minute background deadline. Its initial drafts timed out, repair consumed the remaining budget, and verification stopped before workflow screenshot review.

Full product planning, draft workers and complete-source review now route to GPT-5.4 by the shared build-standard stage marker. Reasoned tool execution and strict verification planning retain their compatible configured model. This split is intentional: an actual synthetic compatibility probe found that GPT-5.4 rejects reasoned function tools on the existing Chat Completions endpoint. Separate real probes confirmed GPT-5.4 medium-reasoning text/JSON and GPT-5-mini medium-reasoning function tools work. Existing provider/model overrides remain supported; there is no claim that all stages use the same model.

Defaults: medium reasoning, 12,000 initial output tokens, a bounded 24,000-token length retry, 48,000 input tokens, 180-second ordinary model calls, and a fifteen-minute background deadline. Screenshot review uses GPT-5.4 with 6,000 output tokens, medium reasoning and a 90-second call bound. Source-aware context protection and overall parent deadlines remain authoritative. These choices can increase API usage and build duration.

Initial drafting has a maximum seven-minute stage deadline and preserves time for compilation, repair and review. Ordinary implementation hands off with three minutes remaining instead of one. Existing repair flow still has the overall job deadline. Completed worker modules survive a sibling worker timeout; complete drafts survive review timeouts. The arbitrary 48,000-character pre-review cutoff was removed in favor of the protected, token-aware context check. These failures cannot silently throw substantial work away and restart from a scaffold.

Regression validation: 56 relevant tests passed, followed by 11 focused API-profile/schema tests after adding non-sensitive phase/model/output/finish-reason logging. Additional checks cover partial worker retention, protected complete source, reserved review time, bounded retries, context limits and the existing delivery-quality gates. A fresh synthetic mini-model game completed generation and complete-source review in 194.7 seconds and compiled. A separate full-model canary is recorded under local verification evidence; no private project source was sent for these diagnostics. Synthetic compatibility does not establish that every future product will meet an identical artistic standard.


The first stronger-model canary exposed a combined JSX/stylesheet generation timeout. The follow-up splits JSX, CSS and logic into three independently owned outputs, tied to an explicit class/layout contract, and allows up to 240 seconds for a design-tier response within the stage deadline. Partial outputs and post-review integration failures retain their source. Regression validation for this split and its budget/retention rules: 39 tests passed. The split-model canary records real request model/phase/limits in non-sensitive logs and saves partial results locally if it cannot finish.


The split-model canary confirmed an actual 12,000-token length finish during a substantial draft. Full design-tier responses therefore now start with a bounded 24,000-token allowance, avoiding an expensive 12,000-token discard/regeneration cycle. Ordinary tool responses retain their 12,000-token initial allowance. This is capacity, not a required response length; generation still stops naturally when complete.
